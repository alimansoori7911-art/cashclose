# تست‌های انتها‌به‌انتها

این تست‌ها روی سرویسِ **در حال اجرا** و دیتابیس واقعی اجرا می‌شوند —
برخلاف تست‌های واحد (`npm test`) که مستقل‌اند.

## پیش‌نیاز

```bash
powershell -File scripts/pg-portable.ps1 start
```

سپس API را بالا بیاورید (`npm run dev:api`) و مطمئن شوید دادهٔ نمونه
ساخته شده است (`npm run db:seed`).

## اجرا

```bash
node tests/regression.mjs
```

پوشش کامل فازهای ۰ تا ۵: احراز هویت، نقش‌ها، مدیریت فروشگاه، هستهٔ
صندوق، آپلود عکس، فلوی حسابدار و جداسازی مستأجر.

```bash
node tests/edge-cases.mjs
```

موارد لبه‌ای و امنیتی: تزریق، ورودی مخرب، مبالغ نامعتبر، دسترسی افقی و
محدودیت نرخ.

## نکته‌ها

- هر دو تست **idempotent** هستند و پسوند یکتا برای هر اجرا می‌سازند.
- اگر صندوق در وضعیت `submitted` گیر کرد، با این دستور پاک کنید:

```bash
npm run db:reset-registers --workspace @cashclose/api
```

- `edge-cases.mjs` عمداً محدودیت نرخ را فعال می‌کند؛ اگر بلافاصله پس از
  آن تست دیگری اجرا کنید ممکن است با ۴۲۹ مواجه شوید. یک دقیقه صبر کنید.
- از `fetch` داخلی Node استفاده می‌شود نه `curl`: در Git Bash ویندوز،
  `curl` بدنه را با codepage سیستم می‌فرستد و متن فارسی خراب می‌شود.
