# تست‌های انتها‌به‌انتها

این تست‌ها روی سرویسِ **در حال اجرا** و دیتابیس واقعی اجرا می‌شوند —
برخلاف تست‌های واحد (`npm test`) که مستقل‌اند.

## پیش‌نیاز

```bash
powershell -File scripts/pg-portable.ps1 start
```

سپس API را بالا بیاورید (`npm run dev:api`) و مطمئن شوید دادهٔ نمونه
ساخته شده است (`npm run db:seed`).

## اجرا

```bash
node tests/regression.mjs
```

پوشش کامل فازهای ۰ تا ۵: احراز هویت، نقش‌ها، مدیریت فروشگاه، هستهٔ
صندوق، آپلود عکس، فلوی حسابدار و جداسازی مستأجر.

```bash
node tests/edge-cases.mjs
```

موارد لبه‌ای و امنیتی: تزریق، ورودی مخرب، مبالغ نامعتبر، دسترسی افقی و
محدودیت نرخ.

```bash
node tests/phase6-reports.mjs
```

هشت گزارش مدیریتی: فرمول پیش‌بینی، فیلتر بازه و شعبه، و این قاعده که فروش
فقط از صندوق‌های تأییدشده شمرده شود.

> پیش‌نیاز این یکی: `npm run db:demo-history --workspace @cashclose/api`
> — گزارش‌های روند و پیش‌بینی بدون چند هفته داده معنا ندارند.

## نکته‌ها

- هر سه تست **idempotent** هستند و پسوند یکتا برای هر اجرا می‌سازند.
- استثنا: صندوق **امروز** ساختنی نیست اگر از قبل وجود داشته باشد (قاعدهٔ
  «یک صندوق در روز»)، پس `regression.mjs` همان را دوباره به کار می‌گیرد و
  نسخه‌ها روی هم انباشته می‌شوند. به همین دلیل تست نسخه‌ها **افزایش** را
  می‌سنجد نه عدد مطلق را. برای شروع تمیز:
  `npm run db:reset-registers --workspace @cashclose/api`
- اگر صندوق در وضعیت `submitted` گیر کرد، با این دستور پاک کنید:

```bash
npm run db:reset-registers --workspace @cashclose/api
```

- **بین دو تست یک دقیقه فاصله بیندازید.** مسیر ورود سقف ۱۰ درخواست در
  ۶۰ ثانیه دارد و هر تست چند بار وارد می‌شود؛ اجرای پشت‌سرهم باعث ۴۲۹
  می‌شود و تست با خطای بی‌ربط (مثلاً «body.every is not a function»)
  می‌شکند — چون بدنهٔ ۴۲۹ شیء خطاست نه آرایه. `edge-cases.mjs` علاوه بر
  این، عمداً محدودیت نرخ را فعال می‌کند.
- از `fetch` داخلی Node استفاده می‌شود نه `curl`: در Git Bash ویندوز،
  `curl` بدنه را با codepage سیستم می‌فرستد و متن فارسی خراب می‌شود.
