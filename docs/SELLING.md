# راهنمای فروش و راه‌اندازی مشتری

این سند برای **شما** است — مالک محصول. مرحله‌به‌مرحله می‌گوید چطور یک
مشتری تازه را راه بیندازید و چه زیرساختی لازم دارید.

---

## ۱. معماری: یک سرور، چند مشتری

سؤال رایج: «برای هر مشتری یک دیتابیس جدا بسازم؟»

**نه.** سامانه از پایه چندمستأجری ساخته شده:

```
یک سرور ← یک دیتابیس ← چند کسب‌وکار (Tenant)
                          ├── فروشگاه رفاه   (کد RFH12345)
                          ├── فروشگاه کوروش  (کد KRS67890)
                          └── فروشگاه شما    (کد ...)
```

هر ردیف دیتابیس ستون `tenant_id` دارد و **هر کوئری** با آن فیلتر
می‌شود. مالک رفاه حتی با شناسهٔ مستقیم صندوق کوروش هم `404` می‌گیرد.

### چرا دیتابیس جدا نه

| یک دیتابیس مشترک | دیتابیس به‌ازای هر مشتری |
|---|---|
| یک مهاجرت برای همه | ۵۰ مهاجرت جداگانه |
| یک نسخهٔ پشتیبان | ۵۰ پشتیبان |
| یک بار مصرف حافظه | ۵۰ اتصال جدا |
| افزودن مشتری = یک فرم | افزودن مشتری = راه‌اندازی سرور |

جداسازی با `tenant_id` انجام می‌شود و آزمون شده است. دیتابیس جدا فقط
وقتی لازم است که مشتری **قانوناً** ملزم باشد داده‌اش روی سخت‌افزار
جداگانه بماند — که برای فروشگاه خرده‌فروشی پیش نمی‌آید.

## ۲. زیرساخت لازم

### حداقل برای شروع

| مورد | مشخصات | هزینهٔ تقریبی |
|---|---|---|
| سرور مجازی | ۲ هسته، ۴ گیگ رم، ۴۰ گیگ SSD | ماهی ۲۰۰–۴۰۰ هزار تومان |
| دامنه | یک دامنهٔ `.ir` یا `.com` | سالی ۵۰–۳۰۰ هزار تومان |
| گواهی SSL | رایگان (Let's Encrypt) | ۰ |

سرور فعلی شما (۲ هسته، ۳۰ گیگ) برای **۱۰ تا ۲۰ مشتری** کافی است.

### چه زمانی باید ارتقا دهید

- بیش از ۵۰ کسب‌وکار فعال
- کندی محسوس در بارگذاری گزارش‌ها
- مصرف دیسک بالای ۷۰٪ (عکس‌های رسید جا می‌گیرند)

---

## ۳. دامنه و زیردامنه

هر مشتری آدرس اختصاصی خودش را می‌گیرد:

```
rafah.cashclose.ir    → فروشگاه رفاه
korosh.cashclose.ir   → فروشگاه کوروش
```

### تنظیم DNS

در پنل دامنه، یک رکورد **wildcard** بسازید:

| نوع | نام | مقدار |
|---|---|---|
| A | `*` | آی‌پی سرور |
| A | `@` | آی‌پی سرور |

با این یک رکورد، **همهٔ زیردامنه‌ها** خودکار به سرور می‌رسند و برای
مشتری تازه نیازی به تغییر DNS نیست.

### چرا زیردامنه

- مشتری فقط آدرس خودش را می‌شناسد
- نام مشتریان شما به رقبا لو نمی‌رود (فهرست کسب‌وکارها عمومی نیست)
- کاربر هیچ کدی تایپ نمی‌کند؛ آدرس خودش می‌گوید کدام مجموعه است

## ۴. راه‌اندازی مشتری تازه — گام به گام

### گام ۱: ورود به پنل مدیر سامانه

```
https://cashclose.ir/platform
```

با نام کاربری و رمز مدیر سامانه وارد شوید.

### گام ۲: «کسب‌وکار تازه»

پنج فیلد:

| فیلد | مثال | توضیح |
|---|---|---|
| نام کسب‌وکار | فروشگاه رفاه | فارسی، برای نمایش |
| شناسهٔ آدرس | `rafah` | زیردامنه‌اش می‌شود |
| نام مالک | حسن رفاهی | |
| نام کاربری | `owner` | در هر کسب‌وکار جداگانه یکتاست |
| رمز اولیه | یک رمز قوی | مالک باید عوضش کند |

### گام ۳: کارت اطلاعات

پس از ساخت، کارتی می‌آید با **کد کسب‌وکار**، نام کاربری و رمز.
دکمهٔ «کپی متن» همه را یکجا کپی می‌کند.

> ⚠️ رمز **فقط همین یک‌بار** نمایش داده می‌شود. جایی ذخیره نشده است.

### گام ۴: ارسال برای مشتری

متن پیشنهادی:

```
سلام،

حساب شما در سامانهٔ صندوق روزانه آماده است:

آدرس:        https://rafah.cashclose.ir
نام کاربری:  owner
رمز عبور:    <رمز>
کد کسب‌وکار: RFH12345

پس از اولین ورود، حتماً رمز خود را تغییر دهید.

کد کسب‌وکار را نگه دارید؛ هنگام تماس با پشتیبانی لازم می‌شود.
```

### گام ۵: مشتری خودش بقیه را می‌سازد

مالک پس از ورود، در «مدیریت فروشگاه» می‌تواند:

- شعبه تعریف کند
- صندوقدار، حسابدار و مدیر بسازد
- کارتخوان تعریف و به صندوقدار تخصیص دهد

**شما در این مرحله کاری ندارید.**

---

## ۵. مدیریت مشتریان

### تعلیق (مشتری تمدید نکرده)

در پنل مدیر سامانه، دکمهٔ «تعلیق» را بزنید:

- کاربرانش دیگر نمی‌توانند وارد شوند
- **داده‌اش پاک نمی‌شود**
- با «فعال‌سازی» همه‌چیز برمی‌گردد

### آنچه شما می‌بینید و نمی‌بینید

| می‌بینید | نمی‌بینید |
|---|---|
| نام، کد، آدرس | صندوق‌ها |
| تعداد شعبه و کاربر | مبالغ |
| تاریخ ساخت، وضعیت | گزارش‌ها |

این عمدی است: همان مرزی که بین مشتری‌ها هست، برای شما هم برقرار است.

---

## ۶. چه چیزی هنوز باید ساخته شود

پیش از فروش جدی، این موارد لازم‌اند:

| مورد | چرا | وضعیت |
|---|---|---|
| **HTTPS** | رمز کاربران الان رمزنگاری‌نشده منتقل می‌شود | ❌ حتماً |
| **پشتیبان‌گیری خودکار** | یک خرابی دیسک = دادهٔ همهٔ مشتریان | ❌ حتماً |
| تغییر رمز توسط کاربر | مالک باید رمز اولیه را عوض کند | ⚠️ فقط مدیر می‌تواند |
| صفحهٔ «رمزم را فراموش کردم» | پیاده شده ولی ایمیل نمی‌فرستد | ⚠️ نیمه |

**دو مورد اول پیش از اولین مشتری واقعی باید حل شوند.**

---

## ۷. پشتیبان‌گیری

بدون پشتیبان، یک خرابی دیسک یعنی از دست دادن دادهٔ **همهٔ** مشتریان.

### پشتیبان روزانه

```bash
docker compose exec -T db pg_dump -U cashclose cashclose | gzip > ~/backup-$(date +%F).sql.gz
```

### خودکار کردن

```bash
crontab -e
```

این خط را اضافه کنید (هر شب ساعت ۳):

```
0 3 * * * cd ~/cashclose && docker compose exec -T db pg_dump -U cashclose cashclose | gzip > ~/backups/db-$(date +\%F).sql.gz
```

> پشتیبان روی **همان سرور** کافی نیست. هفته‌ای یک‌بار روی رایانهٔ خودتان
> یا فضای ابری کپی بگیرید.

### بازگردانی

```bash
gunzip -c ~/backups/db-2026-09-14.sql.gz | docker compose exec -T db psql -U cashclose cashclose
```

## ۸. قیمت‌گذاری — چند نکتهٔ عملی

سامانه از نظر فنی محدودیتی نمی‌گذارد؛ این تصمیم شماست. ولی بدانید:

- **هزینهٔ هر مشتری تازه برای شما تقریباً صفر است** (همان سرور، همان دیتابیس)
- هزینهٔ واقعی: فضای دیسک عکس‌های رسید، و زمان پشتیبانی
- یک فروشگاه با ۵ صندوقدار، ماهی حدود ۱۵۰ صندوق ثبت می‌کند

اگر اشتراک ماهانه می‌فروشید، «تعلیق» ابزار شماست: مشتری تمدید نکرد،
تعلیقش کنید — داده می‌ماند و هر وقت پرداخت کرد برمی‌گردد.
