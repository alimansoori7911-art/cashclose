# سامانهٔ مدیریت صندوق روزانه فروشگاه

سامانهٔ SaaS چندمستأجری برای ثبت، راستی‌آزمایی و بستن صندوق روزانهٔ فروشگاه،
همراه با کنترل حسابدار و گزارش‌گیری مدیریتی.

---

| ابزار | نسخه | وضعیت |
|---|---|---|
| Node.js | ۲۰٫۱۱ یا بالاتر | ✅ نصب است (v22.19.0) |
| npm | ۱۰ یا بالاتر | ✅ نصب است (v10.9.3) |
| PostgreSQL | ۱۶.۴ | ✅ نصب است (قابل‌حمل) |

### PostgreSQL قابل‌حمل

چون روی این سیستم دسترسی ادمین در دسترس نبود، نسخهٔ **قابل‌حمل** نصب شده
است: همان باینری‌های رسمی، ولی بدون سرویس ویندوز و بدون رجیستری.

مسیر نصب: `%USERPROFILE%\pgsql-portable` (خارج از مخزن گیت)

```bash
powershell -File scripts/pg-portable.ps1 start
```

```bash
powershell -File scripts/pg-portable.ps1 stop
```

> **مهم:** دیتابیس با هر بار ری‌استارت ویندوز خاموش می‌شود و باید دستی
> راه‌اندازی شود. برای محیط تولید، نصب معمولی با دسترسی ادمین توصیه
> می‌شود تا به‌صورت سرویس خودکار بالا بیاید.

## راه‌اندازی

```bash
npm install
```

```bash
cp apps/api/.env.example apps/api/.env
```

> فایل `.env` هم‌اکنون ساخته شده و یک `JWT_SECRET` تصادفی دارد. فقط رمز
> دیتابیس را در `DATABASE_URL` اصلاح کنید.

پس از نصب PostgreSQL، جداول و دادهٔ نمونه را بسازید:

```bash
npm run db:migrate --workspace @cashclose/api
```

```bash
npm run db:seed
```

### چرا بستهٔ `shared`؟

فرمول صندوق باید **دقیقاً یکسان** در دو جا اجرا شود: بک‌اند (اعتبارسنجی
قطعی پیش از بستن صندوق) و فرانت‌اند (نمایش زندهٔ اختلاف حین تایپ). اگر دو
پیاده‌سازی جدا داشتیم، هر تغییری ریسک واگرایی داشت. با این بسته، فقط یک
پیاده‌سازی وجود دارد.

## فرمول محاسبه

```
مانده صندوق = Σ(اقلام مثبت) − Σ(اقلام منفی)
جمع اسناد   = چک + کارتخوان + کارت‌به‌کارت + نقدی + ارز + درگاه اینترنتی
اختلاف      = جمع اسناد − مانده صندوق

اختلاف = ۰  →  تراز   (سبز)  →  صندوق قابل بستن
اختلاف > ۰  →  مازاد  (آبی)  →  بستن غیرمجاز
اختلاف < ۰  →  کسری   (قرمز) →  بستن غیرمجاز
```

این فرمول مستقیماً از سلول‌های `B15`، `B17` و `B18` فایل اکسل واقعی
(`docs/صندوق (3).xlsm`) استخراج و با تست خودکار بازتولید شده است.
